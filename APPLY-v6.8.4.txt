WHAT CHANGES
Before any scheduled queue row is created, the server now preflights the selected content and every selected destination against the actual dispatch worker formats:
- Instagram: exactly one media reference containing an HTTPS URL without embedded credentials.
- Facebook Pages: exactly one media reference containing an HTTPS URL without embedded credentials.
- LinkedIn organisations: text-only content (no media references).
- TikTok and YouTube: rejected from scheduled public-post dispatch. Their existing creator-inbox/private-upload workflows remain separate and unchanged.
- Any destination must still be connected and have capabilities.content_publish === true.

The batch is rejected before any queue rows are written if one selected destination is incompatible. This avoids creating a mixed batch that contains destinations the current worker cannot publish. Existing protected Supabase RPCs remain authoritative for workspace membership, role, brand ownership, timezone, scheduling window, duplicate prevention and queue cancellation.

IMPORTANT
- This release does not add new social-platform publishing adapters.
- It does not make TikTok public auto-publishing or YouTube public/scheduled publishing available.
- The existing Instagram/Facebook worker still supports a single HTTPS media reference; LinkedIn supports text-only scheduled dispatch.
- Media reachability, actual MIME type, provider app review and live provider permissions still need live validation.
- The UI already explains the existing format limits. Incompatible selections are rejected using the Publishing Queue's existing invalid-destination message.

VALIDATION EXPECTATION

A green focused test/audit is not a substitute for the full repository test suite, Vercel build, a live controlled post, and verification on each connected provider account.
