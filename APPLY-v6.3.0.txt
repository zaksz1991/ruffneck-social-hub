4. NEW OPERATING FLOW
- Billing setup: `/platform/billing-setup` shows the passive webhook journal and setup status.
- Payment review: `/platform/billing-review` keeps the existing filtered review and separate `APPROVE` action.
- Missing initial-payment webhook: `/platform/billing-reconcile` allows only a platform billing administrator to enter transaction details copied from Flutterwave Dashboard. The database locks the pending RuffNeck invoice and requires exact reference, amount, currency, email and payment-plan matches.
- The new reconciliation record is pending only. Open the normal review queue and complete the separate approval process after checking the transaction in Flutterwave Dashboard again.

LIMITS
Do not use missing-webhook reconciliation for recurring renewals, refunded/reversed payments, failed or pending provider charges, missing plan IDs, mismatched invoice values or invoices that are no longer pending. The reconciliation form never activates a subscription.

VALIDATION
The ZIP contains focused tests and static audits. The complete repository npm test, full production build, actual remote migration and live Flutterwave transaction remain to be verified after installation.
